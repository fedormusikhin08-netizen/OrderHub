# OrderHub — учёт заказов интернет-магазина

Итоговый проект по контрольным точкам **КТ31–КТ39** («Коллекции, LINQ, перечислители и итераторы в C#»).

Консольное приложение, которое последовательно обрастает возможностями:
очередь и стек заказов, история на `LinkedList`, склад на `Dictionary`,
сортировка каталога, отчёты на LINQ, ленивые итераторы и собственная
коллекция `CircularBuffer<T>` с поддержкой `foreach`.

## Как собрать и запустить

```bash
dotnet build OrderHub.sln
dotnet run --project src/OrderHub
```

Требования: .NET SDK 8.0 или новее.

## Ответы на вопросы

Queue — очередь (кто первый пришёл, тот первый ушёл). Stack — стопка (кто последний пришёл, тот первый ушёл).

AddLast сразу даёт закладку на только что вставленный элемент, и вставить рядом по ней — мгновенно. Find каждый раз бегает по всему списку и сравнивает по ссылке, поэтому нужный заказ так не найдёт.

В словаре нет ключа — вернуть нечего, поэтому исключение KeyNotFoundException. Проверяй через TryGetValue: он просто говорит «есть/нет» и отдаёт значение.

IComparable — тип сам знает, как себя сравнивать (один порядок, работает Sort() без аргументов). IComparer — отдельная «линейка» для другого порядка, её передаёшь в Sort. Если нет ни того, ни другого — Sort() 
падает, сравнивать нечем.

Ленивый LINQ — это рецепт: пока не начал готовить (foreach, ToList), ничего не происходит. Каждый перебор — готовишь заново.

IGrouping — группа элементов с ярлыком Key (например, категория). По ней считаешь Count/Sum/Average как по обычной коллекции, только ярлык один на всю группу.

Join — слияние двух списков по общему полю (например, имя клиента). Нет пары — строка выкидывается. Несколько заказов у клиента = несколько строк, потом GroupBy + Sum собирает в одну сумму.

Бесконечный итератор не виснет, потому что yield отдаёт по одному элементу, когда попросят. Take(N) просит только N и останавливает. А ToList() просит всё — вот там и виснет.

В интерфейсах два GetEnumerator с разными типами, одним методом оба не закрыть. Поэтому нужна явная реализация второго, иначе не скомпилируется.

Старейший = (next - size + capacity) % capacity. next — куда писать следующий, size — сколько лежит, +capacity чтобы не уйти в минус.

Один проект — этапы связаны, код растёт, видно систему целиком. Девять заданий — девять раз с нуля, связи не видно.
